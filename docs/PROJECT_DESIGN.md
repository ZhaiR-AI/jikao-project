# 英语学位考试学习系统

这是一个基于 AgentClaw 和本地试卷服务构建的英语学习辅助系统，目标是帮助准备学位英语考试的学习者稳定达到 70 分。

系统的核心原则是：

> 聊天助手负责判断和制定策略，软件负责执行、记录、提醒和复习安排。

软件不替代学习者与聊天助手之间的题目分析。学习者可以把题目、答案、单词、短语和当天学习情况发给聊天助手，由聊天助手判断真正不会的地方；软件负责把这些决定转化成可以完成、可以追踪、不会遗忘的学习任务。

## 产品分工

### 聊天助手负责

- 分析学习者发来的英语题目、答案和思路。
- 按固定流程判断问题：谓语、连接词、主语、时间、主动或被动、词性和语境。
- 判断学习者是不会语法、单词、词组还是翻译。
- 判断学习者是否真正理解，而不是只记住某一道题的答案。
- 记录和总结薄弱知识点。
- 决定每天的学习重点、任务顺序和任务取舍。
- 根据当天学习结果调整第二天的计划。
- 判断哪些任务必须补做，哪些任务可以顺延或暂时删除。

### 软件负责

- 展示当天学习任务。
- 按计划安排开始时间、结束时间和学习时长。
- 提醒任务开始和复习到期。
- 记录任务完成、未完成、暂停和顺延状态。
- 保存单词、短语、错题、薄弱点和每日学习报告。
- 自动安排间隔复习。
- 记录考试作答、判卷结果和错题。
- 提供学习模式和考试模式。
- 汇总正确率、速度、重复错误和距离 70 分的差距。
- 把当天的学习数据整理成可以交给聊天助手分析的报告。

## 学习闭环

系统的完整流程如下：

```text
聊天分析题目
      |
      v
确定薄弱点和复习重点
      |
      v
生成固定格式的每日计划
      |
      v
软件创建任务、提醒、计时和记录
      |
      v
完成学习并提交当天报告
      |
      v
聊天助手判断完成质量并生成下一天计划
      |
      v
软件安排第二天任务和 1/3/7/14 天复习
```

## 每日计划

聊天助手每天结束分析后，应输出固定格式的计划。软件读取这份计划后创建任务。

示例：

```text
今日有效学习时间：3小时40分钟

第一任务：复习单词50个，45分钟
完成标准：随机测试至少40个认识

第二任务：背短语20个，35分钟
完成标准：遮住中文后至少回忆15个

第三任务：做时态语态题10道，40分钟
完成标准：至少做对8道，并解释3道错题

第四任务：订正真题，60分钟
完成标准：完成5道订正，写出每道题的错误原因

晚间复习：重做今天错题，20分钟
完成标准：重新做对至少4道
```

软件需要支持以下任务操作：

- 创建任务。
- 调整任务顺序。
- 设置开始时间和结束时间。
- 开始、暂停、继续和完成任务。
- 标记任务未完成。
- 把未完成任务移动到第二天。
- 根据新计划增加、减少或删除任务。
- 保留历史记录，不因一天没有完成而删除学习数据。
- 提供“暂停今天计划”按钮。

计划调整不能简单地把所有任务堆到第二天。补救任务需要分级：

| 类型 | 处理方式 |
| --- | --- |
| 必须补 | 错题复习、已经到期的间隔复习、核心薄弱点 |
| 可以顺延 | 普通单词复习、普通短语复习 |
| 可以删除 | 低优先级的新内容 |

例如当天只完成 2 小时，第二天应重新安排为复习错题 40 分钟、单词 30 分钟、短语 30 分钟、真题 60 分钟，而不是强行堆积成 6 小时计划。

## 每日学习报告

每天点击“今日学习结束”后，软件应收集并保存以下数据：

- 计划学习时长。
- 实际有效学习时长。
- 单词复习数量和测试正确数量。
- 短语复习数量和测试正确数量。
- 真题完成数量和正确数量。
- 当天向聊天助手咨询过的题目。
- 仍然不会的题目。
- 当天最薄弱的知识点。
- 当天的精神状态和第二天预计可用学习时长。

聊天助手根据这份报告输出固定格式的总结：

```text
今日完成：
今日未完成：
今日新增薄弱点：
已掌握内容：
明日重点：
明日学习时长：
复习安排：1天后、3天后、7天后、14天后
```

在暂时不能自动连接聊天助手时，软件至少应生成一段完整报告，供学习者直接复制到聊天中。

## 错题和不会内容

学习者与聊天助手分析完题目后，应能够保存一条完整的学习记录：

- 原题。
- 学习者的答案。
- 正确答案。
- 错误原因。
- 聊天助手的讲解。
- 对应知识点。
- 学习者自评分类：语法、单词、词组、翻译。
- 下次复习日期。
- 复习次数和是否已经掌握。

示例：

```text
错题：The window ____ by the boy ...
知识点：过去分词作定语
错误原因：以为过去分词必须和 be/have 一起使用
讲解：过去分词可以单独作后置定语，表示被动或完成含义
复习安排：明天做5道，3天后再做5道
```

薄弱点不要求软件自己分析题目。聊天助手分析出结果后，软件负责保存和累计：

- 分词作定语：薄弱。
- 完成时被动：一般。
- 名词所有格：一般。
- 时间表达：薄弱。
- `does + 动词原形`：已掌握。
- `-ing/-ed`：基本掌握。

当某个知识点连续错 3 次时，软件应自动将其标记为重点，供下一次计划优先安排。

## 间隔复习

当天讲过的内容不能只复习一次。默认复习节奏为：

```text
当天晚上 -> 第 1 天 -> 第 3 天 -> 第 7 天 -> 第 14 天
```

适用对象包括：

- 错题。
- 不熟单词。
- 不熟短语。
- 做对但没有把握的题。
- 连续错误的薄弱知识点。

复习不能只是重新看答案，应该优先重新测试：

- 单词：遮住中文或英文进行回忆。
- 短语：在例句中补全或翻译。
- 语法：重新做同类题并说明排除理由。
- 错题：遮住解析重新作答。

## 学习验收标准

软件记录的不能只有“学习了多少分钟”，还需要保存是否达到验收标准：

```text
复习50个单词，随机测试至少40个认识。
背20个短语，遮住中文后至少回忆15个。
做10道语法题，至少做对8道，并解释3道错题。
订正5道错题，第二天重新做时至少做对4道。
```

只有完成标准达成，任务才应显示为“已掌握”或“完成”。如果只是计时结束但没有达到标准，应记录为“完成学习时长，验收未通过”。

## 学习模式和考试模式

### 学习模式

- 可以暂停和继续。
- 可以查看答案和解析。
- 可以向聊天助手提问。
- 可以给每道题标记不会类型。
- 可以保存草稿。
- 可以立即复盘错题。

### 考试模式

- 限时完成。
- 不显示参考答案。
- 不允许中途查看讲解。
- 自动记录开始时间、结束时间和答题时长。
- 可以保存作答，但不能在考试过程中显示判卷结果。
- 交卷后统一判卷。
- 交卷后再把错题和答案交给聊天助手分析。

## 进步数据

进步页面应重点展示与考试结果直接相关的数据，而不是只显示累计学习小时数：

- 单词认识率。
- 短语记忆率。
- 语法题正确率。
- 阅读理解正确率。
- 完形填空正确率。
- 翻译得分率。
- 真题完成速度。
- 错题重复率。
- 最近几次模拟考试分数。
- 各知识点连续错误次数。
- 距离 70 分还差哪些模块。

进步数据应能够表达实际变化，例如：

```text
单词认识率：60% -> 82%
语法题正确率：10道对5道 -> 10道对8道
模拟成绩：55分 -> 66分
```

## 当前已实现功能

当前版本已经完成今日学习和试卷考试的第一轮基础能力：

1. `/study` 今日学习页面展示当天计划和任务执行状态。
2. 可以导入聊天助手生成的结构化计划 JSON。
3. 学习任务支持开始、暂停、继续、完成、重置和顺延到明天。
4. 任务记录计划分钟、实际有效分钟、完成标准和优先级。
5. 可以暂停今天的计划，暂停时会停止正在计时的任务。
6. 可以填写计划时长、实际时长、单词、短语和真题完成情况。
7. 可以保存今天问过的题、仍然不会的内容和新增薄弱点。
8. 保存反馈后自动生成可以复制给聊天助手的日报。
9. 每道试卷题目有 `语法`、`单词`、`词组`、`翻译` 四个分类按钮。
10. 四个分类可以同时选择，例如一道题可以同时标记为语法和词组。
11. 作答内容、分类、标记和逐题笔记会在修改后最多 10 秒内自动保存到本地 JSON，文件名包含卷子名、日期和 UUID。
12. 点击“保存作答”可以手动保存。
13. 刷新或重新打开同一套试卷后，可以恢复上次作答和分类。
14. 提交后保存考试记录、答题时长、总分和每题判卷结果。
15. 保留现有 AI 判卷工作流。
16. 有标准答案的单选、多选和判断题可以直接本地判分。
17. 没有标准答案的题目继续交给 AI 判卷。
18. 答错的题目自动写入本地 JSON 错题本。
19. 错题本保存题干、答案、参考答案、错因、建议和不会类型。
20. `/wrong-book` 提供独立错题本页面，可按状态、不会类型筛选并搜索题干、试卷和笔记。
21. 错题本默认隐藏参考答案，可填写答案后核对，并记录“这次答对了”或“仍需复习”。
22. 重做正确进入“已掌握”；再次做错会重新进入“待重做”，且保留错误次数和重做历史。
23. 可以修改语法、单词、词组、翻译分类，并保存个人订正笔记。
24. 学习页按语法、单词、词组、翻译汇总错题数量。
25. 重新打开试卷时可以恢复最近一次判卷结果。
26. “清空作答”会同时清除答案和四类分类标记。

## 快速开始

### 启动试卷考试页面

在当前 `agent` 目录下双击 `start.bat`，或执行：

```powershell
.\start.ps1
```

启动脚本会使用项目根目录下的 `.venv`，并在当前终端持续输出服务日志。按 `Ctrl+C` 停止服务。

如果服务已经运行，使用 `-Restart` 停止本项目的旧服务进程并重新启动：

```powershell
.\start.ps1 -Restart
```

`start.bat` 同样支持重启参数：

```powershell
.\start.bat -Restart
```

默认访问地址：

```text
http://127.0.0.1:8020/exam
```

今日学习页面：

```text
http://127.0.0.1:8020/study
```

如果需要更换监听地址或端口：

```powershell
.\start.ps1 -ListenAddress "0.0.0.0" -Port 8030
```

也可以继续通过环境变量配置，或直接运行 Python 入口：

```powershell
$env:PAPER_HOST = "127.0.0.1"
$env:PAPER_PORT = "8020"
..\.venv\Scripts\python.exe paper_server.py
```

`paper_server.py` 是独立的试卷 HTTP 服务，不启动 AgentClaw Dashboard；试卷生成和 AI 判卷仍然通过 AgentClaw 工作流执行。

### 试卷生成

生成流程默认使用 3 路 OCR 并发，服务端最多允许 4 路。OCR、套卷切分和题目提取等模型调用遇到瞬时错误时会最多尝试 3 次，并使用递增等待时间降低连续限流风险；重试耗尽后会终止本次生成并返回具体失败阶段，不保存缺题的半成品试卷。

在页面上传 PDF 后，系统会执行以下流程：

```text
paper_generation:
START
  -> prepare_input
  -> render_pdf_pages
  -> ocr_pages
  -> persist_ocr
  -> split_exams
  -> create_exam_jobs
  -> extract_question_chunks
  -> assemble_papers
  -> persist_papers
  -> persist_collection
  -> format_response
  -> END
```

### AI 判卷

提交试卷后，系统会执行：

```text
paper_grading:
START
  -> load_paper
  -> normalize_answers
  -> normalize_paper
  -> flatten_questions
  -> split_grading_items
  -> grade_objective_items
  -> grade_subjective_items
  -> merge_grade_results
  -> format_response
  -> END
```

生成的真题 JSON 目前多数没有标准答案，因此这些题会继续使用 AI 判卷；包含标准答案的客观题则可以本地确定性判分。

## 更新和重启脚本

项目中提供了：

- `update_and_restart.ps1`
- `update_and_restart.bat`

脚本的目标流程是：

```text
进入 frontend
    -> npm run build
    -> 重启 start.ps1/start.bat/start.cmd
    -> 等待服务启动
    -> 重启浏览器并打开页面
```

脚本默认寻找当前目录下的 `frontend` 和 `start.ps1/start.bat/start.cmd`。如果路径不同，需要指定参数：

```powershell
.\update_and_restart.bat `
  -FrontendDirectory "D:\project\frontend" `
  -StartScript "D:\project\start.bat" `
  -Browser chrome `
  -BrowserUrl "http://127.0.0.1:3000"
```

暂时不重启浏览器：

```powershell
.\update_and_restart.bat -SkipBrowserRestart
```

脚本会记录由它启动的进程并在下次更新时尝试重启。重启浏览器会关闭对应浏览器的现有窗口，使用时请确认没有未保存的页面内容。

## 开发约定

- 不让软件替代聊天助手进行学习者能力判断。
- 不把“计时完成”直接当成“已经学会”。
- 所有错题和学习报告保留历史记录。
- 计划调整优先保证错题和到期复习，不无限堆积补做任务。
- 判卷结果不确定时保留人工复核状态，不直接当作错误。
- `.env`、模型密钥、视频、OCR 图片和本地生成数据不应提交到公开仓库。
