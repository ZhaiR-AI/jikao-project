## v0.1.1：真实试卷与新手流程复测

测试从 GitHub 的 v0.1.0 发布页开始，下载实际 ZIP 并核对 SHA-256，阅读包内使用说明，在隔离目录中运行。首次启动不带已有卷子或配置，通过真实启动窗口填写已有模型账号的三项信息。测试进程的 PATH 不包含系统 Python。浏览器使用 Edge，操作真实页面，没有拦截网络请求、替换模型响应或编造题目、答案。

发现并修复：

- Windows 深层目录解压可能超过路径长度限制。发布页、README、包内说明新增短路径解压和完整重新解压指引。
- 真实作文题的编号提纲被误当作题号，同时遗漏了作文主题与字数要求。现在保留完整要求，并检测旧卷遗漏的作文主题。
- OCR 产生的装饰符号阅读标题未被识别。现在接受这类标题，避免不必要的模型提取和不完整结果。
- 启动器生成的模型配置备份和临时文件纳入 Git 忽略规则。

修复后已验证：

- 使用真实试卷汇编中的连续 5 页原卷，重新通过网页上传并调用真实视觉模型，约 38 秒生成 54 道题，完整性状态为 ready。
- 对已有异常生成结果点击“重新整理异常部分”，成功得到 54 道题并通过完整性检查，旧卷保留。
- 通过网页逐题填写既有学习记录中的 54 道真实作答，保存、刷新后内容一致。
- 通过“提交并 AI 判卷”实际调用模型，约 49 秒收到成功响应，返回 54 道题的结果，页面显示 75.5 分，刷新可恢复成绩。该分数仅用于验证结果保存和显示，不代表人工核准的评分准确性。
- 点击启动器“停止服务”后，服务进程和监听端口退出；关闭后重新打开 EXE 自动加载配置，54 道作答、一次判卷记录、75.5 分和 16 条错题仍在。重开后的试卷和错题页无 JavaScript 异常。
- 原来运行中的服务持续可访问；原目录 26 个学习记录文件的 SHA-256 与测试前一致。
- 使用真实历史 OCR 复查另外几份原卷，五份试卷的题目数均保持 54；其中一份仍有待人工核对提示，因此未把所有历史卷宣称为完全通过。

真实 PDF、答案、模型凭证、运行数据和带个人内容的截图仅留在本地，不随源码或 ZIP 发布。一次真实模型成功不代表所有供应商兼容，也不代表所有试卷格式均能准确识别。尚未以新客户身份测试模型平台注册和充值，尚未在另一台电脑或全新 Windows 虚拟机验证。

## v0.1.3：PDF 图片识别与文档读取

检查日期：2026-09-19。使用用户实际运行的便携程序和实际导入的 8 页四级试卷，发现旧结果的 8 页均采用 `pdf_text`：内嵌文字已有大量乱码，导致缺少第 30—35 题，出现空阅读部分及作文分值异常。

已取消 PDF 文字层捷径。PDF 每页交给 VL 模型；旧结果的修复也会重新识别对应页面图片。真实模型识别后，完整结构为作文 1、听力 25、选词填空 10、阅读匹配 10、仔细阅读 10、翻译 1，共 57 个作答项。

在用户实际运行的程序中，通过网页“重新整理异常部分”完成真实修复，8/8 页记录为 `vision_ocr`，题号 1—55 连续，完整性状态 ready。浏览器核对作文 15 分、恢复的空位及 15 个词库选项、普通阅读完整题干和四个选项。原来的 51 题卷子保留，没有覆盖原卷。未重复进行本轮无关的 AI 判卷测试。

听力题已对照原 PDF 页面核查：原卷印的是选项，问题在音频中；页面明确提示需要配套音频。这不属于可以靠图片识别补出的题干。

非 PDF 使用单独的文档读取路径。将同一份真实 VL 识别原文另存为 TXT、Markdown 和纯文字 DOCX，核对读取后所有非空白字符一致，没有编造试题内容。Word 图片、公式对象或不支持的编号会要求先导出 PDF，避免静默丢失内容。

通过实际浏览器上传上述真实 TXT，直接读取 5 个内容段，再实际调用模型完成 4/4 个整理片段，最终生成 57 个作答项，状态 ready，来源标为“段”，页面无 JavaScript 异常。升级隔离测试服务后，通过页面“重试未完成部分”续跑，已完成且格式正确的片段得到保留，旧的不完整缓存被重新整理。DOCX、Markdown 的验证范围是读取内容一致，完整模型流程以 TXT 代表验证，没有声称另外拿到用户原生 Word 文档进行全流程测试。

模型长 JSON 的测试发现了另一个实际缺陷：截断结果中的内部对象曾被当成整段结果。现在只接收完整的外层对象，并检查大题列表；旧的不完整片段缓存会丢弃重试。对实际模型结果及其截断版本进行了针对性检查。

这些检查不代表所有 Word 排版、所有文档编码或所有考试类型均已覆盖。运行证据和真实资料保存在本地被忽略的 outputs 目录。
